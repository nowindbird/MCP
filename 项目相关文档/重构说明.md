## 1. 重构目标

# 第二轮重构（2026-11-02）：去耦合 + 依赖接口统一

> 目标：删掉旧的一次性脚本，把「各模块各拼一套路径 / 各写一套客户端」的耦合收口到
> **单一依赖文件** `detector/deps.py`。**检测口径与判定结果保持不变**（已用真实仓库
> 做新旧对比回归）。

## 1. 新增：`detector/deps.py`（唯一依赖接口）

所有跨模块依赖只从这里取，不再各处重复实现：

| 能力 | 内容 |
|---|---|
| 路径 | `PROJECT_ROOT / DATA_DIR / OUTPUT_DIR / SCAN_OUTPUT_DIR / CACHE_ROOT / SANDBOX_WORK_DIR / SANDBOX_IMAGE_DIR` |
| 配置 | `CONFIG / STATIC_CONFIG / ALIGN_CONFIG / VERDICT_CONFIG / SANDBOX_CONFIG / GITHUB_CONFIG / FETCH_CONFIG` |
| 扫描口径 | `SKIP_DIRS / DOC_SKIP_DIRS / SCAN_EXTS / SPECIAL_FILES / CODE_EXTS / 大小与行长上限` |
| 仓库遍历 | `iter_repo_files / iter_repo_texts / read_readme / detect_languages` |
| 文件 IO | `read_text / write_text / read_json / write_json / read_jsonl / write_jsonl / write_csv / iter_scan_results / load_targets / load_scan_summary` |
| 网络 | `HTTPClient`（重试/限流/硬超时下载）→ `GitHubClient`（tree/raw/search/commits/tarball）→ `LLMClient`（OpenAI 兼容 / Anthropic） |
| 可选依赖 | `require_requests / has_module / docker_available / ensure_ollama / ensure_utf8_stdio` |

`requests` 改为按需导入，**离线功能（扫描 / 对齐 / 沙箱解析）不再依赖它**。

## 2. 删除的过时文件

| 删除项 | 原因 |
|---|---|
| `fetcher/fetch_tarballs.py`、`fetch_tarballs2.py`、`fetch_small_repos.py`、`fetch_retry.py`、`fetch_api_selective.py` | 5 个一次性脚本，各自写死 REPOS 清单 + 复制粘贴同一套下载逻辑 → 合并为 `fetcher/fetch_repo.py`（清单驱动、并发、硬超时、断点续跑） |
| `fetcher/cache_inventory.py` | 盘点逻辑已被 `fetch_repo` 的 `fetch_manifest.csv` 取代 |
| `crawler/organize_plugins.py` | 依赖写死的时间戳文件 `mcp_repos_20260927_205656.json`，早已失效 |
| `scanner/normalize.py`、`aggregate.py`、`report.py` | 三个脚本各自拼 `output/scan_results`、各写一套遍历；且 aggregate 的列口径与 run_flow 读取的列口径**不一致**（接不上）→ 合并为 `scanner/summary.py`，列口径统一在 `deps.SCAN_SUMMARY_FIELDS` |
| `analysis/`（空占位包） | 从未使用 |
| 根 `download_group3.py`、`prep_group3_inputs.py`、`使用说明.txt` | 依赖写死 `C:\Users\...` 绝对路径、绑定已不存在的分组流程 |
| 根临时件：`_d.txt`、`_tmp_read0.txt`、`g3_rerun_*.txt`、`download_group3.log`、`qwen_tags.html`、`__pycache__/` | 调试残留 |
| `uml/` 中对应已删模块的 12 组图（24 个文件） | 图的源文件已不存在，属过时文档；`index.html` 同步清理 |

## 3. 修掉的耦合缺陷

1. **`sys.path.insert` + 平铺导入**（cli / docgen / sandbox_rules / behavior_monitor / run_flow）→ 全部改为 `from detector.xxx import ...`，CI 新增检查防止回退。
2. **静默失效的配置**：`behavior_monitor.py` 里 `sys.path.insert(PROJECT_ROOT)`（应插 `detector/`）导致
   `from config import CONFIG` 永远失败且被 `except` 吞掉，`SBX` 实际是空字典，沙箱参数根本没生效 → 现在直连 `deps.CONFIG`。
3. **路径写进代码目录**：`behavior_monitor` 把 strace/tcpdump/蜜罐写到 `detector/output/sandbox_work` → 改到 `CONFIG` 的 `output/sandbox_work`。
4. **同一份口径四处复制**：跳过目录/扩展名在 scanner、docgen、align、fetcher 各有一份且互不一致 → 收敛到 `STATIC_CONFIG`。
5. **阈值写死**：对齐率判定（0.3/0.6/3）与沙箱规则重复硬编码 → 收敛到 `ALIGN_CONFIG / VERDICT_CONFIG`。
6. **相对路径 + 子进程 cwd 不一致**：`run_flow` 调用 docgen 子进程时 cwd 变化导致清单找不到 →
   统一转绝对路径，并以项目根为 cwd 走 `python -m detector.cli docgen`。
7. **Windows 控制台 emoji 崩溃**：README 含 emoji 时 `print(json)` 抛 `UnicodeEncodeError`（旧代码在老仓库上实测会中断）
   → `deps.ensure_utf8_stdio()` 统一把 stdout/stderr 切到 UTF-8。

## 4. 命令变化

| 旧 | 新 |
|---|---|
| `organize` / `fetch-api` / `fetch-small` / `fetch-tarballs` / `fetch-tarballs2` / `fetch-retry` / `inventory` | `fetch`（`--manifest` 或 `--repos`，`--method auto/tarball/tree`） |

| `pipeline --run scan` | 同左，另支持 `--run a b` 多步与 `--all` |
