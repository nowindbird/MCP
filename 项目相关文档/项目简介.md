# MCP 插件投毒安全检测系统（MPV-Detector）项目简介

> 申报用途：大学生创新创业训练计划（大创）——创新训练项目
> 项目名称：MPV-Detector · 面向 MCP 插件生态的投毒安全检测系统
> 更新日期：2026-10-22

---

## 一、项目思路来源（立项背景与依据）

**政策与技术背景：** 当前以大语言模型为核心的 AI Agent 正在大规模落地，模型上下文协议（MCP, Model Context Protocol）已成为连接智能体与外部工具的事实标准。MCP 插件/Server 被智能体动态加载并调用，天然具备读写文件、执行命令、访问网络、操作凭据等真实系统权限——这使得插件生态成为新兴且高危的攻击面：攻击者可在看似正常的工具中植入恶意逻辑（即"投毒"，Tool Poisoning），诱导智能体执行未声明的敏感操作。然而，目前开源 MCP 生态普遍缺乏面向插件投毒的系统性、自动化检测手段，安全缺口明显。

**理论来源：** 项目核心思路参照安全顶级会议 USENIX Security 2026 论文《"Do Not Mention This to the User..."——恶意 Agent 技能的隐蔽注入与检测》（arXiv:2602.06547）。论文指出，仅靠"扫描恶意关键字"误报率极高，应通过**分层流水线**（采集 → 扫描 → 执行 → 分析）识别插件"声明做什么"与"代码实际做什么"之间的不一致。

**可行性依据：** 团队成员已完成初步工程验证（见"前期研究基础"），证明该技术路线在真实插件仓库上可跑通，具备立项可实施性。

---

## 二、项目目的（研究目标与意义）

1. **构建一套面向 MCP 插件生态的自动化投毒检测系统**，覆盖代码采集、静态扫描、语义分析、沙箱执行全链路，替代人工逐仓排查，形成可复用的工程化安全检测工具。

2. **攻克"单靠关键字扫描误报高"这一核心难题**，核心手段是"插件声明行为 × 代码实际行为"交叉验证：
   - 静态扫描：规则匹配危险模式（敏感路径、动态下载、混淆执行等）；
   - 语义分析：LLM 生成"插件声称做什么"的文档，与 AST 提取的硬事实比对，量化矛盾率；
   - 沙箱执行：Docker 隔离环境内真实运行，采集系统调用、抓包、蜜罐诱捕观测未声明行为。

3. **对真实开源 MCP 插件仓库开展批量检测**，产出可审计、可追溯的判定结果（benign / suspicious / malicious），识别潜在投毒风险，为 MCP 生态安全基线提供数据支撑。

4. **培养团队科研与工程能力**，打通"文献调研 → 方案设计 → 系统实现 → 实验验证 → 成果沉淀"的完整创新训练闭环。

## 三、项目创新点

> 本节分两部分：（一）项目自身创新点概述；（二）以对照表 + 差异化条目，逐项说明本项目相对原论文（USENIX Security 2026, arXiv:2602.06547）的增量贡献。

### （一）项目自身创新点

1. **【核心创新】文档—行为语义对齐率检测**：以 AST 确定性提取的代码硬事实为基准，与 README / description 中插件的公开声明逐条比对，自动计算对齐率 `alignment_rate`、矛盾率 `conflict_rate`、安全相关矛盾率 `security_conflict_rate`，输出 `CLEAN / WARN / DANGER` 分级信号；判定以硬事实为主、LLM 文档为辅，避免模型幻觉，专门捕捉"嘴上说安全、代码干坏事"的文档欺骗与影子特征（与论文的差异化对照见（二）第 1 条）。

2. **三层交叉验证检测体系，破解"误报高"难题**：在语义对齐这一核心信号之上，叠加静态扫描（危险模式命中）与沙箱执行（未声明行为观测），三层独立维度交叉印证，从多个角度相互佐证，显著降低误报、提升可解释性。

3. **面向 MCP 协议特性的定制化检测**：针对 MCP 特有的工具注册/调用机制，设计协议层触发探针与静态规则体系（在论文 14 模式基础上补充 M1–M9，其中 M5–M9 为 MCP 协议层专属规则），实现"载体换锚点"的协议感知检测，比通用代码扫描更贴合插件生态。

4. **领域微调语义模型（核心创新的本地化底座）**：针对 MCP 工具文档领域，用 QLoRA 4bit 微调 Qwen2.5-3B-Instruct（真实 MCP 语料 541 条，loss 0.034，适配器约 117MB），为语义理解与对齐率判定提供本地模型支撑，降低对闭源大模型的依赖、便于本地化部署。

5. **大规模真实生态实测与可追溯判定**：在 800+ 个真实 GitHub MCP 插件仓库上完成批量检测，识别真实凭据硬编码与投毒风险；对 CRITICAL/HIGH 命中逐条复核给出 `verdict + confidence + reason` 可追溯判定，而非简单给"是/否"，兼顾准确性与人工成本。

6. **工程化可复现、可扩展**：统一 CLI + 配置中心化（环境变量优先、无硬编码路径）+ 六段式流水线 + 断点续跑，MIT 开源，方便他人复现与二次开发，具备向 MCP 生态安全基线工具沉淀的潜力。

### （二）相对原论文的差异化创新（论文做法 → 本项目增量）

**对照说明**：原论文是首个大规模 Agent 技能（Agent Skills）安全实证研究，贡献在于带标签基准数据集（98,380 快照 → 4,287 候选 → 157 行为确认恶意、632 漏洞）与威胁表征结论。本项目在沿用其"静态分诊 + 动态验证"同构思路的同时，**最核心的增量创新是把论文提出但未自动化实现的"文档—行为对比"主张，落成可计算、可阈值化的语义对齐率检测**；其余在检测对象、触发方式、模型依赖、运行时闭环与成果形态上构成配套增强，逐项对照如下（★ 为核心创新维度）。

| 对比维度 | 原论文做法与局限 | 本项目 MPV-Detector 的增量创新 |
|---|---|---|
| ★核心：语义分析 | 调用闭源 GPT-5.2 代理对 SKILL.md 自由文本做"是否含指令覆盖/隐藏指令/行为操纵"的**定性分类**；文档与行为是否一致仅靠两位作者人工比较影子特征，未将"公开声明"与"代码事实"做结构化、可量化的对齐比对 | 以 **AST 确定性提取硬事实**（Python 走真 AST 解析，JS/Go/Rust 走正则兜底），与 README / description 中的公开声明逐条比对，自动输出 `alignment_rate`、`conflict_rate`、`security_conflict_rate` 与 `CLEAN / WARN / DANGER` 信号；硬事实为主、LLM 文档为辅，避免模型幻觉，使"文档—行为落差"成为可计算、可设阈值的检测指标，是本项目相对论文最主要的差异化贡献 |

| 静态规则 | 14 个攻击模式：代码层正则匹配，指令层（P1/P2/P4）交由 LLM 代理定性判断；规则面向技能包脚本 | 在论文 14 模式映射基础上扩展规则体系，新增 M1–M9 补充模式，其中 **M5–M9 为 MCP 协议层专属**（工具描述投毒、工具名仿冒/零宽字符、客户端配置投毒、schema 投毒、资源/提示词投毒）；规则覆盖 Python、JS/TS、Go、Java、C#、PowerShell 多语言 |
| 动态触发 | 触发方式为文档化入口点元数据调用 + GPT-5.2 生成合成输入，每技能 3–5 轮、60 秒超时窗口；论文 §5.4 与附录 D 自陈：未确认候选中 **93.2% 为窗口内未激活的休眠触发型**，条件触发、时间延迟、多会话攻击均会漏检 | 自研 **MCP 协议级主动触发探针**：按 stdio JSON-RPC 完成 `initialize → notifications/initialized → tools/list → 按 inputSchema 推导哑参数逐工具 `tools/call` → `resources/list / prompts/list`，主动"使用"插件暴露的每一个注册工具，逼出仅在特定工具 handler 被调用时才执行的恶意逻辑，针对性缓解论文暴露的休眠触发漏检问题 |
| 语义模型（核心创新底座） | 指令层检测与合成调用输入均依赖**闭源 GPT-5.2**，需联网调用外部 API，成本高、不可离线运行、结果难以在本地复现 | 基于 Qwen2.5-3B-Instruct + **QLoRA 4bit**，在 541 条真实 MCP 工具语料（含敏感事实样本；v2 按恶意:良性 = 1:4 混入恶意增强样本）上领域微调，适配器约 117MB；为语义对齐判定提供可本地离线部署的模型底座，检测器在无外网、隐私敏感环境下仍可运行，且便于按 MCP 领域语料持续迭代 |

| 成果形态 | 实证测量研究：带标签数据集 + RQ1–RQ3 威胁态势/攻击策略/规避机制表征 + 负责任披露；流水线服务于论文标注与统计，并非面向生态交付的可复用工具 | 交付面向 MCP 生态的**工程化检测工具**：统一 CLI（`crawl / fetch / scan / docgen / align / finetune / sandbox-rules / monitor / report`）、配置中心化（环境变量优先、无硬编码路径）、六段式流水线、断点续跑、Windows 一键脚本、MIT 开源；已在 800+ 真实 GitHub MCP 仓库批量实测，每条高风险命中附 `verdict + confidence + reason` 可追溯依据 |

**差异化创新条目（可单独引用；第 1 条为核心创新）：**

1. **【核心创新】把论文"文档—行为对比"的定性主张落成可计算的语义对齐指标。** 论文虽指出"文档—行为比较是单一最高收益的检测启发式"，但在方法上仅用 GPT-5.2 对指令文本做是否含攻击向量的定性分诊，文档与行为是否一致依靠两位作者人工比较影子特征，未形成自动化、量化的判定指标。本项目以 AST 硬事实为基准逐条核对公开声明，量化对齐率、矛盾率与安全相关矛盾率并输出 CLEAN / WARN / DANGER 分级信号，使论文所称"84.2% 漏洞嵌入 SKILL.md 等自然语言文档"的核心判断获得可自动化、可阈值化的检测实现；判定以确定性代码事实为准，不依赖模型自由发挥，这是本项目相对论文最主要的差异化贡献。

2. **研究对象由 Agent 技能拓展至 MCP Server 生态，填补论文明确留白的攻击面。** 论文 §3.2 将 MCP 服务器排除在数据集之外；本项目面向 GitHub 上的 MCP Server / 插件，围绕工具注册、公开描述、参数 schema、客户端配置、资源与提示词等 MCP 特有环节设计规则与探针，是论文威胁模型在新协议生态上的延伸与补充。

3. **MCP 协议级主动触发探针，正面回应论文自陈的"休眠触发漏检"短板。** 论文动态验证被动等待入口点调用与合成输入触发，60 秒窗口内大量条件触发型恶意无法激活；本项目探针按 MCP JSON-RPC 协议完成握手、工具枚举与逐工具主动调用，覆盖"插件启动后恶意代码挂在特定工具 handler 上"的场景，提升动态验证对 MCP 插件的触发覆盖率。

4. **本地化领域微调小模型，作为核心创新的离线模型底座。** 论文指令层与合成输入依赖闭源 GPT-5.2；本项目基于 3B 级开源模型用 QLoRA 领域微调，适配器体积小、可本地离线运行，为语义对齐判定提供模型支撑，使检测器在无外网、隐私敏感环境下可用，同时降低对商业 API 的成本与合规依赖。

5. **"对齐基线—规则生成—分级拦截"的运行时自动闭环。** 论文沙箱只做观测与人工复核；本项目把静态/语义层产出的声明事实转化为白名单、黑名单与违规动作规则，在沙箱内按蜜罐暴露、黑名单命中、白名单缺失三级自动响应与送审，形成可复用的运行时防护机制，而非仅产出研究结论。

6. **从实证数据集走向工程化、可复现的开源检测工具。** 论文贡献是带标签基准与威胁统计结论；本项目交付统一 CLI、配置中心化、断点续跑、一键复现的完整流水线，并在 800+ 真实 MCP 仓库上完成批量实测，每条判定附可追溯证据链，具备沉淀为 MCP 生态安全基线检测工具的条件。

**一句话总结：** 本项目从 USENIX Security 2026 论文思路出发，构建"静态扫描 + 语义对齐 + 沙箱验证"三层一体的 MCP 插件投毒检测系统。与原论文面向 Agent 技能、依赖闭源大模型分诊、被动触发并人工复核的路线不同，本项目**最核心的增量是把论文提出但未自动化实现的"文档—行为对比"主张落成可量化的语义对齐率检测**，并配套 MCP 协议级主动触发探针、本地化微调小模型与运行时分级拦截闭环，面向论文未覆盖的 MCP Server 生态；已完成 800+ 真实仓库批量检测与语义模型微调等前期验证，立项后将完善沙箱行为监控、扩充投毒样本库并沉淀为可开源的 MCP 生态安全检测工具。

## 附：项目简介（500 字以内申报版本）

本项目面向模型上下文协议（MCP）插件生态的投毒安全检测问题。AI 智能体大规模调用 MCP 插件，插件具备文件读写、命令执行、网络访问等真实权限，成为高危攻击面，而开源生态普遍缺乏自动化检测手段。

项目思路源于 USENIX Security 2026 论文《"Do Not Mention This to the User..."》。核心创新是将论文"文档—行为对比"主张落成可量化的语义对齐率检测：AST 硬事实逐条比对公开声明，输出对齐率、矛盾率与分级信号，避免幻觉。在此之上构建"静态扫描 + 语义对齐 + 沙箱验证"三层流水线：静态匹配危险模式；沙箱在 Docker 内采集系统调用与网络行为，观测未声明操作。项目定制 MCP 协议触发探针，微调 Qwen2.5-3B 语义模型。区别于原论文面向 Agent 技能、依赖闭源模型与人工复核，本项目聚焦论文未覆盖的 MCP 服务器生态，以协议级主动触发缓解休眠漏检，实现离线模型与可复现工具。

前期已完成 800+ 个真实 MCP 仓库批量检测，识别出凭据硬编码等高风险信号，验证了可行性。立项后将完善沙箱监控、扩充样本库，沉淀为可开源、可复现的 MCP 生态安全检测工具，形成技术报告并力争发表成果。
