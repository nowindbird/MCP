## 二、研究内容

本项目的研究内容围绕"MCP 病毒从实例到规律、从规律到拦截"展开，包含五个方面：① MCP 病毒实例的归集与泛化研究：系统收集已被公开披露的投毒实例（如 Invariant Labs 数学工具投毒、GitHub 官方 MCP 恶意 issue 攻击、postmark-mcp 供应链投毒等），按工具描述投毒、Rug Pull、工具影子、元数据注入、供应链投毒五类机制归纳攻击模式，从个案中提炼可泛化的攻击特征；② 检测规则的生成研究：将攻击特征形式化为可命中的检测规则——代码层生成正则化模式匹配危险行为（敏感路径、动态下载、混淆执行等），在论文 14 种攻击模式基础上扩展 M1–M9 补充规则（其中 M5–M9 为 MCP 协议层专属），覆盖 Python、JS/TS、Go、Java 等多语言插件；③ 语义对齐检测研究（核心）：用大模型阅读插件代码生成"它声称做什么"的说明文档，与 AST 提取的代码硬事实逐条比对，量化对齐率、矛盾率与安全相关矛盾率；④ 基于对齐结果的拦截规则自动生成：由声明事实自动生成白名单、黑名单与违规动作，在 Docker 沙箱内按三级策略实时拦截未声明行为；⑤ 大规模实测与数据集建设：在 800+ 真实 GitHub MCP 仓库上运行全链路流水线，构建"静态—语义—行为"三层标注数据集，并研究检测结果的可视化呈现与网站化服务。

## 三、国内外研究现状和发展动态

国外方面，MCP 投毒研究自 2025 年起迅速升温。攻击侧：Invariant Labs 于 2025 年 4 月首次演示工具描述投毒，5 月演示针对 GitHub 官方 MCP 服务器（1.4 万 star）的恶意 issue 攻击链；Koi Security 与 Snyk 于 2025 年 9 月确认首个在野恶意 MCP 服务器 postmark-mcp；此后 ShareLock 多工具阈值投毒、MCP-ITP 隐式投毒等新攻击持续出现，实测对主流智能体攻击成功率普遍超过 60%。防御侧：USENIX Security 2026 论文《"Do Not Mention This to the User..."》构建了 9.8 万快照的大规模恶意 Agent 技能基准，提出"静态分诊+动态验证"流水线，并指出"文档—行为比较是最高收益的检测启发式"；SHIELDMCP（ACL 2026）以透明代理实现调用前描述校验、参数清洗、响应分析三段运行时拦截，将攻击成功率从 74% 降至 9% 以下；MCP-Scanner（EnCyCriS 2026）融合关键词、语义与 LLM 评估做静态扫描；MCP-Guard 提出 manifest 签名与 LLM-on-LLM 语义审查；OWASP 已发布智能体应用 Top 10 风险清单，Linux 基金会 SAFE-MCP 计划编目了 80 余种攻击技术。国内方面，中国科学技术大学与北航联合发布 MCPTox 基准，在 45 个真实 MCP 服务器上评测 20 个智能体，多数攻击成功率超 60%；MCP-SafetyBench 提出覆盖服务器、宿主、用户三侧的多轮安全评测；安全内参等媒体对 MCP 生态"暗面"进行了系统报道。总体看，国内外研究呈"攻击披露快、防御刚起步"的格局：现有防御多停留在定性分类、运行时代理或人工复核，尚缺将"声明—行为落差"量化并自动生成拦截规则的工程化系统，这正是本项目的切入点。

## 四、创新点与项目特色

① 核心创新——语义对齐检测：针对"单靠扫关键字误报极高"的难题，本项目以 AST 确定性提取的代码硬事实为基准，与插件 README/description 的公开声明逐条比对，自动计算对齐率、矛盾率与安全相关矛盾率，输出 CLEAN/WARN/DANGER 分级信号，专门捕捉"嘴上说安全、代码干坏事"的文档欺骗，判定以硬事实为主、大模型为辅，避免模型幻觉，把论文提出但未自动化的"文档—行为对比"主张落成可计算、可阈值化的指标。② 语义对齐驱动的拦截闭环：不停留在"检测出可疑"，而是由对齐产出的声明事实自动生成白名单、通用黑名单与违规动作规则，在沙箱内按"蜜罐暴露即判恶意、黑名单命中即拦截、白名单缺失即送审"三级响应，实现"语义对齐—文档生成—规则拦截"的自动闭环。③ 面向输入输出多态的全覆盖检测：MCP 投毒载荷可多态出现在工具描述、参数 schema、客户端配置、资源与提示词乃至工具返回内容中，本项目规则与探针同时覆盖插件的输入侧（描述/schema/配置）与输出侧（返回内容/间接注入），应对载荷位置的多态性。④ 轻量可控的沙箱方案：基于 Docker 容器隔离与 Python 编排实现沙箱执行，按 MCP JSON-RPC 协议主动逐工具调用逼出休眠恶意逻辑，采集系统调用、网络抓包与蜜罐诱捕信号，部署门槛低、可复现。⑤ 本地化模型底座：QLoRA 4bit 微调 Qwen2.5-3B，适配器仅约 117MB，无外网、隐私敏感环境下仍可运行，摆脱对闭源大模型的依赖。

## 五、技术路线、拟解决问题及预期成果

技术路线采用六段式流水线（已实现于 detector 工程包）：① 采集（crawler 模块）：抓取 GitHub 上的 MCP 插件仓库元数据并按嫌疑度排序；② 代码获取（fetcher 模块）：tarball / tree+raw 多通道拉取完整源码；③ 静态扫描（scanner 模块）：正则化规则库匹配危险模式，输出 CRITICAL/HIGH 命中；④ 语义分析（analyzer 模块）：本地微调大模型生成插件说明文档，AST 提取硬事实，计算语义对齐率与矛盾率，生成拦截规则；⑤ 沙箱执行（executor 模块）：Docker 隔离环境内运行 MCP 协议探针，strace 采集系统调用、tcpdump 抓包、蜜罐文件诱捕，按三级规则实时拦截；⑥ 汇总统计（pipeline/report）：融合三层信号输出 LOW / REVIEW / HIGH_RISK_REVIEW 判定与可追溯证据链（verdict + confidence + reason），并通过前后端网站可视化呈现。拟解决的关键问题：关键字扫描误报率高的问题（以语义对齐交叉验证破解）；休眠触发型恶意漏检问题（以协议级主动探针破解）；检测结果到运行时防护的断层问题（以拦截规则自动生成破解）；对闭源大模型的依赖问题（以本地化微调模型破解）。预期成果：端到端 MCP 投毒检测系统 1 套（开源）；静态、语义、行为三层标注数据集 1 套；检测服务网站 1 个；全网 MCP 插件扫描数据报告 1 份；力争发表论文/软著。

## 六、项目研究进度安排

项目周期为一年（2026 年 11 月—2027 年 10 月），分五个阶段推进。**第一阶段（2026.11—2027.01）研发攻坚**：完善检测引擎，迭代静态规则库 M1–M9 的多语言覆盖；提升语义对齐率在恶意样本上的召回；补齐恶意样本重训微调模型；完成 Docker 沙箱行为监控模块的稳定部署，打通"静态筛候选→语义定基线→沙箱验证"三级流水线。**第二阶段（2027.02—2027.04）前后端开发**：设计并实现检测服务网站——后端封装检测流水线为 REST API（任务提交、进度查询、结果拉取、报告生成），前端实现插件上传/仓库地址提交、三层检测结果可视化（对齐率图表、命中详情、沙箱行为时间线）、判定证据链展示与历史记录管理。**第三阶段（2027.05—2027.06）数据集建设**：整合静态扫描、语义对齐、沙箱行为三层结果，完成投毒样本配对标注，形成可公开的三层数据集。**第四阶段（2027.07—2027.08）全网扫描**：对全网公开 MCP 插件仓库批量运行流水线，统计投毒比例、攻击类型分布与高危模式，撰写全网扫描数据报告。**第五阶段（2027.09—2027.10）总结验收**：网站上线试运行并收集反馈，整理技术报告与论文/软著材料，完成项目结题。各阶段设月度例会与里程碑检查，研发与前后端开发并行推进、滚动迭代。

## 八、已具备的条件，尚缺少的条件及解决办法

已具备的条件：① 技术储备——团队已掌握静态分析（AST/正则规则）、大模型微调（QLoRA）、容器化（Docker）与 Python 工程化开发能力，核心检测流水线已在 800+ 真实仓库上跑通；② 数据基础——已积累 800+ 仓库的扫描结果、541 条真实 MCP 微调语料、完整的投毒案例库，并接入论文官方基准 MaliciousAgentSkillsBench 用于对照评测；③ 工具环境——本地 Ollama 大模型推理环境、Docker 沙箱环境、GitHub 采集通道均已配置可用，项目以 MIT 协议开源、配置中心化管理，便于协作与复现；④ 指导支持——指导教师在系统安全与人工智能方向具有研究经验，可提供方向把关与论文指导。尚缺少的条件及解决办法：① 恶意样本数量不足——投毒正样本稀少制约模型训练与检测率评估，拟通过"良性仓库配对注入投毒"的方式构造对照样本，并持续跟踪公开披露补充在野样本；② 算力有限——批量语义分析对显卡有一定要求，拟采用 3B 级小模型加 4bit 量化降低门槛，并申请学校算力平台支持；③ 网站开发与部署经验——团队成员以安全研究为主，前后端工程经验相对薄弱，拟采用 FastAPI + Vue 的轻量技术栈、参照开源管理后台模板快速搭建，并邀请有 Web 开发经验的同学加入；④ 全网扫描的带宽与存储开销——拟采用分片清单、断点续跑与增量更新策略控制成本。

## 九、预期结果

项目预期形成"一套系统、三层数据、一个网站、一份报告"的成果体系：① 系统成果——端到端 MCP 插件投毒检测系统 MPV-Detector 正式版，统一 CLI 入口覆盖采集、扫描、语义对齐、沙箱执行、报告全流程，支持断点续跑与一键复现，以 MIT 协议开源，具备沉淀为 MCP 生态安全基线工具的条件；② 数据成果——构建并公开发布"三层数据集"：第一层为静态扫描数据集（规则命中与危险模式标注），第二层为语义对齐数据集（插件声明、代码硬事实、对齐率/矛盾率及人工复核标签），第三层为沙箱行为数据集（系统调用、网络流量、蜜罐触发与拦截记录），三层相互印证，为后续研究提供首个面向 MCP 投毒的多维标注基准；③ 平台成果——检测服务实例化网站上线运行，支持用户提交仓库地址在线检测，可视化展示三层结果与证据链，让"投毒检测"从命令行工具变成可公开访问的安全服务；④ 报告成果——基于全网公开 MCP 插件的大规模扫描，产出数据报告一份，量化生态中投毒比例、攻击类型分布、高危行为模式与生态安全基线，为业界与学界提供参考；⑤ 学术与育人成果——形成项目技术报告 1 份，力争发表学术论文或申请软件著作权，参加相关学科竞赛；团队成员完整经历"文献调研—方案设计—系统实现—实验验证—成果沉淀"的科研训练闭环，在 AI 安全方向形成可持续的研究积累。
