# 项目结构说明

本文档说明 MPV-Detector 当前代码与研究资料的边界。重构遵循“先建立边界、再迁移代码、最后清理冗余”的顺序；未经验证不删除实验数据或上游基准。

## 当前核心模块

| 路径 | 职责 | 管理原则 |
|---|---|---|
| `detector/cli.py` | 命令行统一入口 | 所有可执行任务从这里暴露 |
| `detector/config.py` | 路径、模型和阈值配置 | 新配置优先通过环境变量或配置文件注入 |
| `detector/crawler/` | GitHub MCP 项目采集 | 只负责元数据采集 |
| `detector/fetcher/` | 项目源码获取 | 下载结果与代码逻辑分离 |
| `detector/scanner/` | 静态规则扫描与结果归一化 | 规则、扫描器、聚合报告分层 |
| `detector/analyzer/` | LLM 文档生成、语义对齐及微调 | 模型调用与分析逻辑分离 |
| `detector/executor/` | MCP 探测、沙箱和行为监控 | 不可信代码只能在隔离环境执行 |
| `detector/pipeline/` | 多阶段流程编排 | 只编排，不重复实现业务逻辑 |
| `mcp插件/` | 插件元数据及部分本地项目 | 数据，不作为 Python 源码包 |
| `mcp_doc_finetune/` | 微调语料、配置和训练产物 | 按数据/配置/模型产物区分；大模型权重不入 Git |
| `MaliciousAgentSkillsBench/` | 上游研究基准及其代码 | 保留上游目录结构、许可证和来源说明 |
| `paper/` | 本项目论文材料 | 论文源文件、参考文献、图表与实验记录分开 |
| `docs/` | 项目维护文档 | 架构、安装、使用、开发和研究记录 |
| `tests/` | 自动化测试 | 单元测试与集成测试分开 |

## 推荐目标结构

当前核心检测代码仍保留在 `detector/`，暂不整体迁入 `src/`，避免一次性迁移导致导入路径和历史 CLI 失效。待兼容性测试完善后，再考虑标准 src-layout。

```text
.
├── detector/                 # 核心检测包
├── configs/                  # 可移植配置模板（逐步迁移）
├── docs/                     # 架构、安装、使用、开发文档
├── experiments/              # 可复现实验脚本与实验配置
├── skills/                   # 可分发 Agent Skills
├── datasets/
│   ├── raw/                  # 原始数据，只读保存
│   ├── processed/            # 清洗/转换后的数据
│   └── samples/              # 小型测试样本
├── outputs/                  # 本地运行产物，不提交大文件
├── paper/                    # 论文源文件与图表
├── tests/
│   ├── unit/
│   ├── integration/
│   └── fixtures/
├── mcp插件/                   # 兼容现有路径，后续按数据迁移计划整理
├── mcp_doc_finetune/         # 独立微调子项目与语料
└── MaliciousAgentSkillsBench/ # 上游基准，保留原貌
```

## 路径与依赖约定

1. 不在代码中写入个人电脑绝对路径。
2. 项目路径由配置模块统一解析；新增路径必须有默认值和环境变量覆盖方式。
3. 原始数据不可被扫描流程原地覆盖；中间结果与最终报告写入独立输出目录。
4. 不把模型权重、缓存、下载源码、运行日志和个人配置提交到 Git。
5. 不在核心模块中隐式执行 Docker、网络下载或模型推理；这些操作应由明确的 CLI 子命令触发。
