# 重构计划与清理记录

## 本次重构原则

- 在独立分支 `refactor/project-structure-2026` 进行，不直接改动 `main`。
- 先盘点，再移动；先验证，再删除。
- 不删除原始数据集、论文 PDF/翻译、上游基准、训练语料或模型配置。
- 所有可疑文件先进入待确认清单；清理必须有依据。
- 保持现有 `python -m detector.cli ...` 命令兼容，除非另行提供迁移说明。

## 初步盘点

### 保留

- `detector/`：当前主检测代码，按 crawler、fetcher、scanner、analyzer、executor、pipeline 分层。
- `mcp插件/`：插件元数据和本地项目数据，不能因目录较大就删除。
- `mcp_doc_finetune/`：包含不同版本语料、训练说明和模型相关目录，需先检查训练脚本引用再决定是否合并。
- `MaliciousAgentSkillsBench/`：上游基准数据与代码，保留来源、许可证和原始目录结构。
- `malicious-agent-skills-2602.06547.pdf`、`论文_中文翻译.md`、`论文代码对接梳理.md`：研究依据和项目映射材料。

### 待确认，不直接删除

- `qwen_tags.html`：看起来是模型标签/网页快照，需确认是否仍用于模型选择或文档。
- `现有问题.txt`：短期问题记录，建议整理进 GitHub Issues 或 `docs/KNOWN_ISSUES.md` 后再归档。
- `一键跑完.ps1`：Windows 工作流入口，需验证是否仍与当前 CLI 一致；在替代脚本完成前保留。
- `requirements-finetune.txt` 与微调子目录：属于可选依赖，不应并入核心运行依赖。

## 分阶段实施

### Phase 1：文档和边界（本分支）
- 增加目录职责说明。
- 明确数据、代码、实验产物、论文材料的边界。
- 更新根 README 的导航与运行说明。

### Phase 2：代码与配置治理
- 逐一检查模块导入、CLI 子命令和路径计算。
- 将硬编码路径迁移到统一配置。
- 拆分核心依赖与可选依赖（LLM、Docker、微调）。
- 为关键路径补充单元/集成测试。

### Phase 3：数据与历史文件整理
- 对数据集建立清单、来源、版本和校验值。
- 将运行产物从版本控制中排除。
- 仅删除可重新生成且确认未被代码/文档引用的缓存或重复文件。
- 对不再维护的实验脚本保留归档说明或 Git 历史。

### Phase 4：Skill 封装
- 在 `skills/mpv-security/` 建立独立 Skill。
- Skill 通过稳定 CLI 调用检测器，不复制检测器业务代码。
- 将示例输入、输出 schema 和安全限制写入 Skill 文档。

## 验收标准

- `python -m detector.cli --help` 可正常执行。
- 现有关键 CLI 子命令的帮助信息可正常加载。
- 核心模块 import 测试通过。
- 小型 fixture 的静态扫描和报告生成测试通过。
- 默认配置不依赖个人电脑绝对路径。
- 未经确认的研究数据和上游代码没有被删除。
